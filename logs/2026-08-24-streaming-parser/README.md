The previous bookmark import feature used a simple dialog interface that allowed users to import bookmarks via a file upload or a share code. While functional, this approach introduced severe performance bottlenecks and lacked scalability, making it difficult to implement flexible, advanced management features. To address these limitations, both the user interface and the underlying import architecture are currently undergoing a complete redesign.

The primary performance bottleneck in the legacy system stemmed from processing files entirely on the main UI thread. When a user selected a bookmark HTML file, the main thread read and parsed the entire document synchronously before offloading the data to a web worker for secondary processing. Consequently, the user interface would freeze completely for several seconds. This issue scale dramatically with file size; importing files containing 200 or more bookmark links consistently caused the application to hang.

To resolve the main thread freezing, the architecture is transitioning from synchronous, main-thread parsing to a stream-based approach handled entirely in the background. Instead of reading the whole file on the main thread, the raw file handle is passed directly to a web worker. Within the web worker, streaming utilities such as the ReadableStream and TextDecoder APIs are used to read the HTML payload in continuous, manageable chunks. The worker then incrementally decodes and parses these incoming chunks on the fly, eliminating the need to load, decode, and parse massive files in a single, block-heavy operation.

Moving to a streaming architecture in a background worker optimizes memory consumption and keeps the main user interface completely responsive regardless of file size. This continuous processing model ensures that bookmark imports remain fast, scalable, and reliable even when handling exceptionally large files.
